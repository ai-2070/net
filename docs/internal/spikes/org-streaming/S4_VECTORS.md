### The fixture contract

`streaming_opening_vectors.json` (GENERATED by
`cargo run -p net-mesh-sdk --features net,cortex,fixtures --example
gen_org_error_fixtures`; drift guard + Rust conformance =
`… --example gen_org_error_fixtures -- --check`, ONE render implementation
shared by writer and checker):

- **`error_vocabulary`** — the frozen `org:` vocabulary (24 vectors + 4
  unclassified cases) embedded from the ONE source (`render_error_vectors()`,
  parsed and re-emitted with byte-pin fields), so the streaming file is
  self-contained and cannot drift from `error_vectors.json`.
- **`opening_vectors` (6)** — the byte-exact streaming OPENING envelope wire
  forms (`OrgStreamCallProof` over the frozen issuance chain): kind 1/2/3 ×
  {granted, owner_delegated}, each with the stream wire, the unary-domain wire,
  the shared pre-signature prefix, the two transcript-domain signatures
  (`net-org-call-v1` vs `net-org-stream-call-v1` — domain separation pinned),
  and the u64 inputs as decimal STRINGS (JS float64 would silently corrupt
  `proof_expires_at_unix_ns`).
- **`decoder_rejects` (8) + `signature_rejects` (1)** — real mutations of a base
  wire (trailing byte, three truncations, kinds 0/4/255, over-cap; one flipped
  signature byte that must DECODE and then fail verify). Decoder disagreement
  must not become success.
- **`scenarios.mixed_pair`** — the one mixed-pair vector: service, request and
  3 chunk byte sequences, the handler-side facts to pin (ids derived from the
  X2 scenario seeds), the exact terminal.
- **Byte pins everywhere** — every vector carries its wire bytes in TWO
  encodings (`wire_hex` + `wire_base64`) plus `wire_len`: a runtime must
  recover identical bytes from both before any other handling (the
  flip-sensitive **byte-for-byte pin**; chosen over sha256 because no digest
  crate is reachable from the generator without editing `sdk/Cargo.toml`
  outside this lane — the dual-encoding cross-check has the identical
  flip-detection property with zero dependency surface in four languages).
- **`credentials` / `streaming_opening_frozen_credentials.json`** — the frozen
  issuance chain (membership A/B, dispatcher A/B, grant B→A), minted ONCE via
  `--mint-frozen` (issuance is nondeterministic by design: RNG nonces + wall
  clock; the deterministic `issue_at` seams are `pub(crate)`). `--check` proves
  every blob's signature verifies and round-trips canonically (`from_bytes`
  alone does not verify signatures).
- **`notes`** — the four harness-integrity rules verbatim: malformed/unknown
  errors, narrowing IDs, callback loss, or decoder disagreement MUST NOT become
  success.

## 4. Findings

**F-S4Vectors-1 — RETRACTED (2026-09-23, after `R4CoreFix`'s instrumented-wheel
trace).** The originally-filed mechanism ("scoped discovery does not cross
OS-process boundaries", with three named core sites) was **wrong**: the red was
a consumer-side bug in this lane's own `mixed_pair/provider.py`, which
discarded the `net.serve_org_streaming(...)` return handle. `ServeHandle`'s
`Drop` (`mesh_rpc.rs:468`) RAII-deregisters the service
(`unregister_rpc_inbound` + `rpc_local_services.remove_if` + protected-stream
retirement), so the granted service was deregistered before the first
announcement: `granted_snapshot()` stayed empty, `SendEmission.scoped` sealed
nothing, and the caller planned against an empty private plane forever. The
"process boundary" correlation was which SCRIPT ran: every red run used
`provider.py` (the Go row and the Python↔Python isolation both spawn it), while
every green cell binds its serve handle (`test_org_live.py`'s `handle = …` +
`finally: handle.close()`; Go's `sh, err := ServeOrgStreamingBytes` + `defer
sh.Close()`). `R4CoreFix`'s trace is the discriminating evidence (receipt at
`docs/internal/spikes/org-streaming/r4corefix-diag-pythonpair.log`): every
`send_emission_to` carried `scoped=0`, the emission build block was never
entered, and the caller-side `capture_cold` showed `grant lookup HIT
(installed=1)` with 0 rows — the three named core sites innocent. Fixed in
`provider.py` (the handle is bound for the serve lifetime with a `finally`
close; the RAII rule is now stated at the handler surface). **Zero core
changes required.** The lesson for harness authors: a serve handle is a
lifetime token — dropping it is a silent unregister.

**F-S4Vectors-2 (informational, already resolved):** the plan's Stage 4 table
names the fixture `streaming_opening_vectors.json` while the dispatch sketch
said `golden_vectors_streaming.json`; Main ruled the plan's name. The lane used
`streaming_opening_vectors.json` throughout.

Roster corrections found by the rows themselves (the conformance rows caught
two wrong constants in the lane brief — vocab vectors are 24 not 25, and the
postcard signature field's length prefix is `0x40` not `0x41`): recorded as
evidence that the rows discriminate; both consumers and the Go file carry the
