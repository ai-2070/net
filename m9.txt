feat(net): stage 6 - the operator surface for the announced STUN endpoint

`mesh.rs` resolves and emits it; the CLI, the wire row and Deck carry
it.

**One resolution rule, in one place.** `rtc_public_stun_addr()`
returns `stun_public_addr` when the operator set one, else the
address the second socket ACTUALLY bound, else `None`. The emission
point and `GET /rtc/anchor` both read that accessor, so they cannot
disagree, and a `:0` bind announces a real endpoint rather than
`ip:0`. Same reason the bootstrap URL already falls back to the
driver's `local_addr` twenty lines above: an announcement names what
exists and never guesses a port.

`--rtc-stun-bind` and `--rtc-stun-public-addr` mirror the existing
`--rtc-bind` / `--rtc-public-addr` pair exactly - same shapes, same
optionality, off by default. The flag-to-config mapping came out of
`run_serve` into `rtc_config_from_args` so it is testable without
binding a socket or booting a mesh.

`rtc_stun_addr` is the same spelling in `anchor ls`, the serve report
and the anchor-directory wire row, omitted when unset. The serve
report is deliberately asymmetric - the new field skips when absent
while `rtc_addr` keeps emitting `null` - because changing the
sibling's rendering is a consumer-visible decision and not this
slice's to take. That is commented where a reader will hit it.

**The end-to-end witness is the one that matters.** A unit test
cannot see announce -> ingest -> nRPC -> CLI JSON, and a field that
never survives that path is exactly the failure this amendment
exists to prevent. `anchor_ls_live` now boots a second real anchor
with a real second socket and asserts the EXACT announced string
arrives beside a distinct `rtc_addr`; the existing anchor asserts the
key is ABSENT. Its inverse - dropping the projection in
`AnchorDirectoryRow` - makes the value vanish from the CLI JSON while
the anchor still announces it, which is precisely the seam where a
field gets lost between the mesh row and the operator.

Deck's `widest_cell()` measures through `cell()` rather than
duplicating its formatting, so the column width cannot disagree with
the text it sizes, and a mesh with no announced endpoint lays out to
the character as before.

One doc correction worth its own line: `rtc_addr`'s comment no longer
calls it "the RTC/STUN socket". That phrase is the plan-level
conflation §6.12.1 identified, sitting in a doc comment.
